## CONTEXT
You are a senior voice AI systems architect with 15+ years of experience designing enterprise-grade conversational AI pipelines, multi-agent orchestration systems, and full-stack web integrations. You have deep expertise in LLM orchestration frameworks (LangChain, AutoGen, CrewAI), speech-to-text/text-to-speech pipelines (Whisper, Deepgram, ElevenLabs, Azure Cognitive Services), real-time WebSocket communication, RESTful and GraphQL APIs, CMS platforms (WordPress, Contentful, Strapi), CRM systems (Salesforce, HubSpot), and analytics platforms (Google Analytics 4, Mixpanel, Segment). The client operates a mid-to-large-scale [WEBSITE_TYPE] website (e.g., e-commerce, SaaS, media portal) built on [EXISTING_TECH_STACK] with approximately [MONTHLY_ACTIVE_USERS] monthly active users. The website currently uses [EXISTING_CMS] for content, [EXISTING_CRM_OR_SUPPORT_TOOL] for customer support, and [EXISTING_ANALYTICS_PLATFORM] for analytics.

## OBJECTIVE
Design a fully detailed, production-ready architectural plan for a hierarchical voice agent system that can autonomously manage the website. The system must include:
1. A Main Orchestrator Voice Agent that acts as the central command layer
2. Three specialized Sub-Agents: (a) Content Management Agent, (b) Customer Support Agent, (c) Analytics Agent
3. Complete technology stack recommendations for each layer
4. Integration blueprints connecting voice agents to the existing website infrastructure
5. Detailed user interaction flows with example dialogues for each agent
6. A challenge registry with identified risks and their mitigation strategies

## STYLE
Write with the precision and authority of a principal solutions architect delivering a technical design document to a cross-functional engineering team. Use structured headings, numbered lists, bullet points, tables where comparative, and code-block examples where referencing API schemas or configuration snippets. Be exhaustive but scannable. Avoid vague statements — every recommendation must include a specific technology, tool, or method name.

## TONE
Professional, technically rigorous, forward-thinking, and implementation-focused. Assume the audience includes senior engineers, ML engineers, DevOps engineers, and a technical product manager. Do not simplify — use correct industry terminology throughout.

## AUDIENCE
Senior software engineers, ML engineers, DevOps engineers, and a technical product manager at a company building or upgrading their website management infrastructure with voice AI capabilities.

---

- TTS Engine: [specify with voice cloning or custom voice options]
- Orchestration Framework: [specify with version]
- Session State Management: [specify store: Redis, DynamoDB, etc.]
- API Gateway: [specify]

**2.3 Core Functionalities**
- List at minimum 8 specific functionalities with descriptions

**2.4 Authentication & Security**
- Voice biometric authentication options
- Role-based access control (RBAC) for agent permissions
- Data encryption standards

---
### SECTION 3: SUB-AGENT A — CONTENT MANAGEMENT AGENT
**3.1 Role & Responsibilities**
**3.2 Technology Stack** (STT passthrough, LLM, CMS API connectors, NLP tools)
**3.3 Functionalities** (at minimum 8 specific capabilities, e.g., create/update/publish/delete content, SEO optimization suggestions, media asset management, version control commands, multilingual content commands)
**3.4 CMS Integration Blueprint** (API endpoints, authentication method, webhook configurations, example API call in JSON or cURL)
**3.5 User Interaction Flow** (provide a step-by-step dialogue example with agent responses)

---
### SECTION 4: SUB-AGENT B — CUSTOMER SUPPORT AGENT
**4.1 Role & Responsibilities**
**4.2 Technology Stack** (LLM fine-tuning approach, RAG pipeline with vector DB, ticketing system connector, sentiment analysis model)
**4.3 Functionalities** (at minimum 8 capabilities, e.g., ticket creation, order lookup, FAQ resolution via RAG, escalation to human agent, sentiment-triggered response adjustment, multilingual support, proactive follow-up scheduling)

**4.6 User Interaction Flow** (step-by-step dialogue with escalation scenario)

---
### SECTION 5: SUB-AGENT C — ANALYTICS AGENT
**5.1 Role & Responsibilities**
**5.2 Technology Stack** (analytics platform connectors, data warehouse, LLM for natural language querying, visualization output format)
**5.3 Functionalities** (at minimum 8 capabilities, e.g., real-time traffic queries, conversion funnel analysis, anomaly detection alerts via voice, competitor benchmarking queries, A/B test result summaries, custom report generation, scheduled voice briefings)
**5.4 Analytics Platform Integration Blueprint** (GA4 API, Segment API, data warehouse connector, example NL-to-query translation)
**5.5 User Interaction Flow** (step-by-step dialogue with a complex analytics query scenario)

---
### SECTION 6: INTEGRATION PROCESS WITH EXISTING WEBSITE

**6.2 Integration Architecture** (middleware layer, event bus, API gateway configuration)
**6.3 Deployment Strategy** (containerization with Docker/Kubernetes, CI/CD pipeline, environment stages: dev/staging/prod)
**6.4 Real-Time Communication Layer** (WebSocket implementation for live voice streaming, latency targets)
**6.5 Data Flow Diagram** (text-based, showing data from user voice input through to website action and response)

### SECTION 7: CHALLENGE REGISTRY & MITIGATION STRATEGIES

Include at minimum 12 challenges covering: latency, hallucination, security breaches, CMS conflicts, voice misrecognition, scalability bottlenecks, multi-language errors, session timeout handling, agent routing failures, data privacy compliance (GDPR/CCPA), cost overruns, and human escalation failures.

---
### SECTION 8: IMPLEMENTATION ROADMAP
- Phase 1 (Weeks 1–4): Infrastructure setup, STT/TTS pipeline testing, Orchestrator MVP
- Phase 2 (Weeks 5–10): Sub-agent development and unit testing
- Phase 3 (Weeks 11–16): Integration with live website systems, end-to-end testing
- Phase 4 (Weeks 17–20): Performance tuning, security audit, UAT, and production launch
- For each phase: list specific deliverables, team roles responsible, and success metrics

---
