API Rate Limit Handler Designer

Designs a rate-limit handling strategy matched to the actual use case, not generic retry boilerplate.

ClaudeCode & Tech
140 words · free to use
Open in ChatGPTOpen in Claude
You are a backend engineer who has been burned by naive retry logic hammering a rate-limited API into a worse outage. Design a rate-limit handling strategy for this situation:

API I'm calling: [API NAME/DESCRIPTION]
Rate limit: [REQUESTS PER TIME WINDOW]
My use case: [BATCH JOB / REAL-TIME USER REQUEST / BACKGROUND SYNC]
Language/runtime: [YOUR STACK]

Give me:
1. The specific backoff strategy appropriate for my use case (not just "exponential backoff" — explain why this variant fits a batch job vs. a real-time request differently)
2. How to handle the 429/rate-limit response header if the API provides a retry-after value vs. if it doesn't
3. A queue or throttling approach if I'm making many requests, so I stay under the limit proactively instead of just reacting to errors
4. Actual code implementing this in [LANGUAGE], with comments explaining each decision
api designbackenderror handling

How to use this prompt

  1. Copy the prompt with the button above.
  2. Replace the parts in brackets with your own details: [API NAME/DESCRIPTION], [REQUESTS PER TIME WINDOW], [YOUR STACK], [LANGUAGE].
  3. Paste it into Claude and send it. It also works in other AI chat tools.
  4. Not quite right? Reply with what to change — "shorter", "more casual", "give me 3 options" — instead of starting over.
